# #867 — [IoT][OTA][Safety] Firmware flashes update even when rollback state cannot be persisted

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/867

---

## Component
IoT firmware — OTA safety / NVS persistence

## Source evidence
- `firmware-esp32/src/ota/ota_update.cpp:344-350` writes `otaLogId`, `otaToVer`, `otaFromVer`, `otaBootN`, and `otaPend` before flashing, but ignores every boolean return value.
- `firmware-esp32/src/config/nvs_store.cpp:66-100` explicitly returns `false` when NVS open/write fails.
- `firmware-esp32/src/ota/ota_update.cpp:354-366` continues download, switches the boot partition, and restarts even if the durable verify/rollback state was not stored.
- On the next boot, `otaBegin()` enters verify mode only when `otaPend == 1` (`ota_update.cpp:434-454`). A failed `otaPend` write therefore bypasses health verification and application rollback entirely.

## Reproduction
1. Enable OTA and return a valid update artifact/checksum/logId.
2. Fault-inject an NVS full/corrupt/open failure before the writes at lines 346-350.
3. Observe `nvsPut*` return false while `downloadAndFlash()` still runs and the device restarts into the new partition.
4. Reboot the new firmware and observe `otaPend` missing, so it is treated as a normal boot and is never health-checked or rolled back.

## Actual
The safety metadata is best-effort. Flashing can proceed without a durable record of the prior/target version, boot counter, pending verification, or rollback report.

## Expected
OTA must abort before writing/switching partitions unless all rollback metadata is durably committed and read back successfully. State should be versioned/checksummed or atomically staged, and all subsequent clear/report writes must handle persistence failure explicitly.

## Impact
A transient NVS failure can turn a recoverable bad OTA into an unrecoverable device deployment, silently bypassing the advertised rollback protection.

## Acceptance criteria
- Check every NVS result and verify the committed state before flashing.
- Do not call `Update.end(true)` or restart when rollback state is unavailable.
- Add fault-injection tests for failure of each OTA state write, partial state, full NVS, and reboot recovery.
- Emit a diagnostic/status failure that is observable by operators.
