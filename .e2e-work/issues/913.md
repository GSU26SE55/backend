# #913 — [BatteryService][OTA Upload][Storage] Invalid and partial binaries become permanent orphan files

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/913

---

## Component

`[BatteryService][OTA Upload][Storage]` — validation, atomicity, and cleanup of uploaded firmware binaries.

## Source evidence

- `AdminIotFirmwareReleasesController.cs:273-294` checks only non-empty file and `.bin` extension.
- Endpoint request cap is 60 MiB (`:259-261`), but no `File.Length <= 50 MB`, Version, or HardwareRevision validation runs before `File.Create` at `:302-325`.
- The separate release command rejects missing Version/HardwareRevision and `ArtifactSizeBytes > 50_000_000` (`CreateIotFirmwareReleaseCommand.cs:39-50`).
- Upload and metadata creation are separate; there is no linkage/retention/delete worker for files never attached to a release. Cancellation or write exceptions can also leave partial final-named files.

## Deterministic reproduction

1. Upload a 55 MB file named `.bin` with empty Version and HardwareRevision.
2. Observe upload 201 and a full file under the firmware storage root.
3. Attempt release creation with the returned metadata; observe validation 400.
4. Repeat; the default 2 GiB PVC can be exhausted with a few dozen authorized requests. Also cancel a streaming upload and inspect the partial file.

## Actual result

Artifacts that can never become valid releases are permanently written under final names. Failures/cancellation and abandoned two-step workflows have no cleanup.

## Expected result

All metadata/size constraints are validated before allocation, writes are temporary/atomic, and uncommitted artifacts have explicit lifecycle cleanup.

## Impact

An authorized admin mistake or repeated request fills persistent storage, leaves misleading binaries, and can take File/OTA functions offline. Partial files may be mistaken for complete artifacts.

## Acceptance criteria

- Validate required metadata, enum/length constraints, and the same 50 MB byte limit before creating a file.
- Stream to a `.part`/temporary object, verify actual length/SHA, and atomically commit the final name.
- Delete temporary/partial data on cancellation or any exception.
- Link uploads to release metadata through a transaction/state machine or expire unattached artifacts safely.
- Add tests proving rejected/oversized/cancelled/failed-create flows do not increase durable file count/usage.
- Add quota/metrics/alerts for firmware storage consumption.
