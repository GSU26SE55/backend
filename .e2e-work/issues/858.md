# #858 — [IoT][MQTT Commands] set_interval ACKs success but is lost after reboot

Priority: priority: P3
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/858

---

## Component
ESP32 command persistence

## Evidence
Provisioning persists the poll interval, but `main.cpp:503-509` set_interval only updates in-memory `s_provCfg.pollingIntervalMs` and always returns true. `command_handler.cpp:67-85` therefore ACKs success. Boot reloads the old NVS value.

## Reproduction
Provision 5s, command 2s, observe success ACK/runtime 2s, reboot: device returns to 5s.

## Expected / acceptance
Atomically persist the validated value before success ACK, return failed and retain the prior value on NVS error, and add reboot/power-loss/boundary tests with an applied configuration revision.
