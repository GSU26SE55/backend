## Mô tả

`SohPredictionBackgroundService` chỉ raise alert khi `Classification ∈ {Degrading, Failed}` (`:165-166`), trong khi AI có thể trả `Normal` kèm `risk.priority = P1` và `warnings[TEMP_CRITICAL]`. Sự cố nhiệt/anomaly nghiêm trọng do đó **không sinh alert, không sinh ticket**.

Output: điều kiện raise alert xét cả `Priority`; severity = mức cao hơn giữa classification và priority; AnomalyType suy từ warning code để ticket được phân loại + SLA đúng bản chất; chi tiết warning/risk được lưu lại trên alert.

## Scope

- Điều kiện raise alert xét `Priority ∈ {P1, P2}` song song với `Classification`
- Severity = mức cao hơn giữa (classification) và (priority): `Critical > Warning`
- AnomalyType suy từ warning code `severity = "critical"` đầu tiên, fallback `SohDegradation`
- Thêm cột `Alert.AiEvidence` (text, nullable) lưu JSON `risk_level` / `priority` / `action_code` / `warnings[]` + EF migration

- Dedup theo AnomalyType **đã tính** thay vì hardcode `SohDegradation`
- Expose `AiEvidence` qua `AlertDto`
- Unit + integration test: `Normal + P1`, `Normal + P2`, `Failed + P1` (không duplicate), `Normal + P3/None` (không alert)

**Ngoài scope:**
- ai-module (Python) — không sửa `/predict`, model, ngưỡng warning
- Không thêm `AnomalyTypeEnum` mới — tránh đổi wire value cross-service (TicketService + NotificationService + FE enum)
- Không đổi `MapAnomalyToB3` / `MapAnomalyToCategory` bên TicketService

- Không đổi luồng Prescribe ngoài việc đổi gate từ `Classification == Failed` sang `severity == Critical`

## Approach

### 1. Severity resolution — lấy mức cao hơn, một nhánh raise duy nhất

Gộp hai nguồn tín hiệu trước khi quyết định. Đúng một nhánh raise → thoả AC "không duplicate với classification branch" theo **cấu trúc**, không phải bằng thêm `if` kiểm tra trùng.

| Classification | Priority | Severity | Ghi chú |
|---|---|---|---|
| Normal | None / P3 | *(không alert)* | Hành vi cũ |
| Normal | P2 | Warning | **Mới** — AC #1 |
| Normal | P1 | Critical | **Mới** — repro của issue |
| Degrading | None / P3 | Warning | Hành vi cũ |
| Degrading | P1 | Critical | Nâng theo risk |
| Failed | bất kỳ | Critical | Không bị P2/P3 hạ xuống |

### 2. AnomalyType suy từ warning code

```
TEMP_CRITICAL / TEMP_HIGH  -> Overheat        (SingleAsset, High)
TEMP_LOW                   -> Undertemp
VOLTAGE_HIGH               -> Overvoltage
VOLTAGE_LOW                -> Undervoltage    (NoPower)
SOH_LOW                    -> SohDegradation
(khac)                     -> SohDegradation  (fallback)
```

Lấy warning `severity="critical"` đầu tiên, không có thì phần tử đầu. Hệ quả: `Overheat → (SingleAsset, High)` + category `Overheat`, thay vì `(SingleAsset, Low)` + `Performance`.

### 3. ThresholdValue / ActualValue / Unit theo loại alert

Hiện hardcode `80m / SohPercent / "%"` (`:287-289`) — đúng cho SOH, sai cho alert nhiệt.
`SohDegradation` → giữ nguyên; type khác → cả ba `null` (đều nullable), chi tiết ở `AiEvidence`.

### 4. AiEvidence

JSON `{ risk_level, priority, action_code, warnings[] }`. Chỉ ghi khi thực sự có tín hiệu (tránh cột toàn `{}`). Cột `text` nullable — `warnings[]` không giới hạn số lượng.

### 5. Dedup theo AnomalyType đã tính

`RaiseSohAlertAsync` hardcode `a.AnomalyType == SohDegradation` (`:274`). Khi type biến thiên phải dedup theo **chính type sắp tạo** — nếu không, alert `Overheat` do AI sinh sẽ bị alert `SohDegradation` đang mở nuốt mất.

### 6. Gate Prescribe

Đổi `Classification == Failed` (`:173`) → `severity == Critical`. Nhất quán với quy ước "chỉ Critical mới tạo ticket" (`:297`).

## Edge Cases

| Case | Hành vi mong đợi |
|------|-----------------|
| `Normal` + `None`/`P3`/rỗng | Không alert (hành vi cũ) |
| `Priority` chuỗi lạ (`"p1"`, `" P1 "`, `"HIGH"`) | `Trim().ToUpperInvariant()` xử lý `p1` / ` P1 `; `HIGH` không match → không raise theo risk |
| `Normal` + `P1`, `warnings` rỗng | Vẫn raise Critical, type fallback `SohDegradation`, `AiEvidence` chỉ có risk block |
| `Failed` + `P2` | Critical — không bị hạ |
| `Failed` + `warnings=[TEMP_CRITICAL]` | Type = `Overheat` — warning critical mô tả sự cố cấp bách hơn |
| Nhiều warning critical | Lấy phần tử đầu — deterministic |
| Warning code chưa biết | Fallback `SohDegradation`, không mất alert |
| Có alert `SohDegradation` mở + prediction ra `Overheat` | Tạo alert mới (khác type) — hai sự cố khác nhau |
| `AiEvidence` khi không risk lẫn warning | `null`, không ghi `"{}"` |
| Response cũ thiếu `warnings`/`risk_level` | List rỗng / `null` → lùi về đúng hành vi hiện tại |
