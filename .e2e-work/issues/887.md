# #887 — [SmsService][Gateway][Security] Stale targeted SMS can be claimed by another gateway

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/887

---

## Component
SmsService — gateway claim ownership and OTP confidentiality

## Evidence
- `SmsMessage.cs:32-33` defines non-null `TargetDeviceCode` as claimable only by that device.
- `ClaimPendingMessagesCommandHandler.cs:58-66` applies the target predicate to Pending rows, but the stale Sending branch at line 63 omits target/current-gateway checks.
- Lines 68-78 and 100-107 reassign ownership and return phone number plus plaintext message.

## Reproduction
1. Queue an OTP SMS with `TargetDeviceCode=device-B`.
2. Let Device B claim it, then make `PickedAt` older than five minutes while status remains Sending.
3. Device A calls `GET /api/sms-gateway/messages/pending`.
4. Device A receives the targeted phone/message and ownership changes to A.

## Actual
Any active gateway can claim stale targeted SMS, bypassing the target confidentiality boundary.

## Expected
Target predicate must apply to Pending and stale Sending. Cross-device failover must require explicit audited reassignment.

## Impact
A compromised/incorrect gateway can obtain user phone numbers and live OTP/message plaintext intended for another device.

## Acceptance criteria
- Apply target/ownership authorization to every claim branch.
- Add explicit audited failover policy if cross-device reassignment is required.
- Test stale targeted-to-self, targeted-to-other, broadcast stale, and concurrent claims.
- Unauthorized gateway receives neither metadata nor message and creates no Picked audit.
