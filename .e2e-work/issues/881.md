# #881 — [IoT][Serial CLI][Security] The set apikey command prints the plaintext API key to logs

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/881

---

## Component
IoT firmware — Serial CLI credential handling

## Evidence
- `firmware-esp32/src/cli/serial_cli.cpp:52-55` logs every complete command line with `Serial.printf("[cli] > %s", line)` before dispatch/redaction.
- Lines 115-126 implement the supported `set apikey <K>` credential command.
- Therefore the exact plaintext key is emitted before `identity::setApiKey()` stores it; later masking in `identity::printStatus()` does not protect this earlier log.

## Reproduction
1. Open the serial console or any collector that captures device serial output.
2. Enter `set apikey iotk_TEST_SECRET_VALUE`.
3. Observe `[cli] > set apikey iotk_TEST_SECRET_VALUE` in plaintext, followed by the success message.

## Actual
A secret entered through the official provisioning/repair interface is copied into serial logs and potentially CI/lab support captures.

## Expected
Credential-bearing commands must never echo their argument. Logging should identify only the command name and success/failure with a masked fingerprint if needed.

## Impact
Device API keys can be recovered from serial logs and used to impersonate the device against BatteryService until rotated.

## Acceptance criteria
- Parse/redact before any command logging.
- Never print API key, MQTT password, Wi-Fi password, or future secret arguments.
- Clear command buffers after use where practical.
- Capturing-logger/serial tests assert seeded secrets do not appear for success, validation failure, overlength, or unknown-command paths.
- Document rotation steps for potentially exposed lab keys.
