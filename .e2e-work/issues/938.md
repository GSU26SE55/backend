# #938 — [Helm][AuthService][Google OAuth] Rendered callback URI contains an unmapped /auth-service prefix

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/938

---

## Component

`[Helm][AuthService][ApiGateway][Google OAuth]`

## Severity

P1 Critical — Google login is deterministically unavailable in every deployment rendered from the Helm chart.

## Source evidence

- `deploy/helm/solar-battery/templates/shared/configmap.yaml:32` renders `GoogleOAuth__RedirectUri` as `https://api.<domain>/auth-service/api/auth/google/callback`.
- `services/ApiGateway/src/ApiGateway/appsettings.json:15-23` exposes Auth API traffic only at `/api/auth/{**catch-all}`.
- The `/auth-service/...` prefix is defined only for Auth Swagger at `appsettings.json:763-771`.
- `services/AuthService/src/AuthService.Api/Controllers/AuthController.cs` combines `[Route("api/auth")]` with `[HttpGet("google/callback")]`, so the callback endpoint is `/api/auth/google/callback`.

## Deterministic reproduction

```text
helm template solar-e2e deploy/helm/solar-battery \
  --show-only templates/shared/configmap.yaml
```

Rendered value:

```text
GoogleOAuth__RedirectUri: https://api.capstonegsu26se55.mooo.com/auth-service/api/auth/google/callback
```

1. Deploy the chart and start Google login.
2. AuthService sends the rendered URI to Google as `redirect_uri`.
3. After consent, Google redirects the browser to `/auth-service/api/auth/google/callback`.
4. Gateway has no matching route for that path, so the request never reaches `AuthController.GoogleCallback` and returns 404.

`helm lint` reports `1 chart(s) linted, 0 chart(s) failed`; syntax validation cannot detect this cross-component semantic route mismatch.

## Actual

The generated public callback URL contains a service prefix that Gateway uses only for Swagger, followed by the complete Auth controller path.

## Expected

The Helm callback URI must be the actual public Gateway route: `https://api.<domain>/api/auth/google/callback`, and it must match the OAuth provider registration exactly.

## Impact

- Google OAuth has a 100% callback failure rate in Helm staging/production.
- Users cannot complete login/linking through Google.
- Authorization codes and state cookies expire without reaching AuthService, obscuring the failure as an external OAuth problem.

## Acceptance criteria

- Render the callback as `/api/auth/google/callback` with no `/auth-service` prefix.
- Define one canonical public base URL/path used by the chart, AuthService, Gateway, docs, and Google provider registration.
- Add a Helm semantic test that resolves every rendered callback/webhook URL to an actual Gateway route.
- Add a deployed smoke test: login redirect contains the configured URI, callback reaches AuthService, state validation executes, and invalid test code returns an Auth response rather than Gateway 404.
- Cover staging and production domain overrides.

## Dedupe

No existing issue through #936 covers the Helm Google callback route. This is distinct from provider-secret configuration and from generic Gateway production routing defects.
