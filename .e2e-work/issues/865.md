# #865 — [AuthService][2FA][RateLimit] Challenge token in request body is ignored by the limiter partition

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/865

---

## Component
2FA verification rate limiting

## Evidence
The documented request is POST JSON `{challengeToken, code, isBackupCode}` and policy promises 5 attempts/5min/token. `RateLimitingExtensions.cs:73-91` reads only `X-Challenge-Token`; despite its comment, it never reads query/body and falls back to RemoteIpAddress.

## Runtime reproduction
Send six requests with six distinct body challenge tokens and no undocumented header: statuses are 422 for the first five and 429 for the sixth.

## Actual
Distinct challenges share one IP partition. Behind Gateway/NAT this can deny 2FA verification for unrelated users; fixing forwarded IP in #812 still leaves per-client-IP instead of per-challenge behavior.

## Expected / acceptance
Use a safe pre-parsed endpoint value/header that the public contract actually requires, bind it consistently to the body token, avoid logging secrets, and test distinct/same challenge plus proxy/NAT behavior.
