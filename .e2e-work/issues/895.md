# #895 — [EmailService][Privacy/Logging] Recipient email and provider response are written raw to logs

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/895

---

## Component

`[EmailService][Privacy/Logging]` — outbound email consumers and Mailjet provider error handling.

## Evidence

The project privacy requirements in `overall.md:4089,6371` forbid logging email/phone PII, but recipient addresses are interpolated verbatim by:

- `SendAdminInviteConsumer.cs:63,67`
- `SendEmailChangeOtpConsumer.cs:67,71`
- `SendPasswordResetOtpConsumer.cs:72,76`
- `SecurityAlertConsumers.cs:77,81,155,159`
- `SendNotificationEmailConsumer.cs:74-81`
- `SendOtpRegisterConsumer.cs:34,57` (`Console.WriteLine`)

In addition, `EmailSenderService.cs:101-106` includes the complete Mailjet response body in an exception. Consumers log that exception with `LogError`, persisting provider-controlled response content together with the raw recipient.

## Steps to reproduce

1. Configure a capturing logger and publish any supported email event with `ToEmail=alice.secret@example.com`.
2. Exercise both a successful send and a Mailjet non-success response containing a recognizable response-body sentinel.
3. Search the captured application output.

## Actual result

Success/failure logs contain the exact recipient address. Provider failures can additionally persist the raw Mailjet response body. Registration OTP also bypasses structured logging through `Console.WriteLine`.

## Expected result

Logs contain only a correlation/event/account identifier or an irreversibly masked/hashed address. Provider failures expose only the HTTP status and an allow-listed safe provider error code.

## Impact

PII and potentially provider-returned sensitive content are copied into centralized logs, backups, and observability systems, expanding access and retention beyond the email workflow.

## Acceptance criteria

- Centralize recipient redaction and apply it to every success/failure consumer path.
- Remove `Console.WriteLine` and raw response bodies from production logging.
- Log only safe Mailjet status/error metadata with correlation IDs.
- Add capturing-logger tests proving raw recipient and response-body sentinels never occur in logs.

## Verification performed

All existing Email consumer tests pass (25/25), confirming this is a missing privacy assertion rather than a currently detected test failure.
