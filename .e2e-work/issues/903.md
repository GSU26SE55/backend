# #903 — [IoT][CI][Coverage] MQTT infrastructure changes do not trigger the infra validation workflow

Priority: priority: P3
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/903

---

## Component

`[IoT][CI][Coverage]` — path filters for MQTT infrastructure validation.

## Source evidence

- `.github/workflows/firmware-ci.yml:17-27` triggers pull/push runs only for `firmware-esp32/**` and the workflow file itself.
- The `infra-lint` job at `:128-155` validates `infra/docker-compose.dev.yml`, `infra/mqtt/docker-compose.yml`, Mosquitto scripts, bootstrap, and secret history.
- No `infra/**` path appears in either the pull-request or push trigger.

## Steps to reproduce

1. Create a branch from `dev` and change only `infra/mqtt/docker-compose.yml`, `infra/mqtt/mosquitto/config/acl.conf`, or one of `infra/mqtt/scripts/*.sh`.
2. Open a PR to `dev` or `main`.
3. Inspect Actions/checks for the commit.

## Actual result

`firmware-ci` is not triggered, so the Compose parse, Shellcheck, and secret-history checks intended for that exact change are skipped. They run only when an unrelated firmware/workflow path also changes or via manual dispatch.

## Expected result

Any file consumed by `infra-lint` triggers that validation on PR and push. Required checks cannot be bypassed by an infra-only commit.

## Impact

Broken broker Compose, ACL, TLS/certificate scripts, password tooling, or secret-control regressions can merge without the repository's declared infra gate.

## Acceptance criteria

- Add the exact `infra/**` inputs used by `infra-lint` to both PR and push path filters (or move infra validation into a dedicated workflow).
- Include Mosquitto config/ACL, Compose files, scripts, bootstrap, and relevant documentation/config generators.
- Add a workflow-trigger regression check (for example actionlint/unit fixtures) for infra-only diffs.
- Configure the resulting job as a required check for protected branches.
- Demonstrate one infra-only PR that runs and passes all infra validation steps.
