# #835 — [IoT][Offline Queue] Telemetry enqueue succeeds when idempotency sidecar persistence fails

Priority: priority: P3
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/835

---

## Component
Firmware offline queue

## Evidence
`local_queue.cpp` treats the idempotency sidecar write as best effort. Legacy/missing sidecar entries are flushed without an idempotency key, and HTTP omits an empty header.

## Actual
A power/storage failure between payload and sidecar writes creates queued telemetry that can be replayed without its stable dedupe identity, causing duplicates after reconnect.

## Expected / acceptance
Persist payload and idempotency identity atomically or derive a deterministic key from the record; quarantine corrupt legacy entries; add filesystem fault and reboot tests.
