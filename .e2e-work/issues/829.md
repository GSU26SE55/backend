# #829 — [BatteryService][IoT][Security] MQTT ingress bypasses device scopes and revoked/disabled state

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/829

---

## Component
Battery MQTT bridge authorization

## Evidence
HTTP ingestion validates API-key revocation, device status and scopes. The MQTT bridge resolves only DeviceCode and `!IsDeleted`, then treats the device as authenticated; handlers do not re-run scope/status checks. Command dispatch can also target Disabled devices.

## Actual
A broker credential/topic path can ingest categories not granted to the device and continue operating after API revocation/disable, diverging from the HTTP security contract.

## Expected / acceptance
Enforce one canonical device authorization policy for HTTP and MQTT, including status, revocation, site and capability scopes; reject command dispatch to inactive devices; add broker integration tests for each denied state.
