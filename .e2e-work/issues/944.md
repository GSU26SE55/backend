# #944 — [AuthService][Roles][Soft Delete] Recreating a deleted custom role fails with an unhandled unique violation

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/944

---

## Component

`[AuthService][Roles][Soft Delete][Administration]`

## Severity

P2 High — deleting a custom role permanently tombstones its name, while recreation passes validation and crashes with a unique violation.

## Source evidence

- `CreateRoleCommandHandler.cs:28-39` checks only visible/non-deleted roles; Auth's global query filter also hides deleted roles.
- `DeleteRoleCommandHandler.cs:61-68` soft-deletes an unused custom role.
- `RoleConfiguration.cs:61,64` combines an unconditional unique index on `NormalizedName` with a global `!IsDeleted` query filter.
- The create path does not restore the deleted role or catch/map the database uniqueness race.

## Deterministic reproduction

1. As Admin, create an unused custom role named `Auditor`.
2. Delete that role successfully.
3. Create another role named `Auditor`.
4. The create precheck cannot see the deleted row and reports the name available.
5. PostgreSQL rejects the insert with `23505`; the request returns an uncontrolled 500.

There is no role-restore endpoint, so the name remains unusable indefinitely.

## Actual

Soft-deleted role names remain globally reserved by the database but are treated as available by application validation.

## Expected

Role deletion/recreation semantics must be explicit and consistent, with controlled conflict handling and no database exception escaping as 500.

## Impact

- Admin cannot recreate an accidentally deleted custom role using its business name.
- Automation that reconciles a desired role catalog repeatedly fails.
- A routine admin lifecycle produces a server error instead of an actionable response.

## Acceptance criteria

- Restore the deleted role, provide a restore endpoint, or use a partial unique active-name index.
- If names are intentionally permanent, detect the tombstone and return a stable 409 before insert.
- Catch concurrent unique violations and map them to the same result.
- Define behavior for old role-permission relationships when restoring.
- Add create→delete→recreate, normalized-case, concurrent-create, and restore/reconciliation tests.

## Dedupe

Distinct from #939 (account email collision) and all role-assignment/permission issues; this is custom-role name lifecycle consistency.
