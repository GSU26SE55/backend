# #853 — [BatteryService][AI][Cancellation] Fallback clients swallow cancellation and invoke HTTP fallback

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/853

---

## Component
Battery AI prediction and prescription fallback clients

## Evidence
The contract says fallback only for Unavailable/DeadlineExceeded/Internal. `FallbackAiPredictionClient.cs:44-72` and `FallbackAiPrescriptionClient.cs:39-66` catch every RpcException and then every HTTP exception. Cancelled RPC therefore invokes HTTP; OperationCanceledException is converted to null.

## Reproduction
Return gRPC StatusCode.Cancelled with the caller token cancelled. Result is `null` and the HTTP fallback call count is 1.

## Expected / acceptance
Propagate caller cancellation, never invoke fallback when cancelled, whitelist only intended transient transport statuses, do not fallback auth/validation errors, and test Predict plus Prescribe HTTP-call counts.
