# #869 — [IoT][INA226][Safety] I2C read failures are published as valid zero-voltage readings

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/869

---

## Component
IoT firmware — INA226 redundant telemetry / BatteryService cross-source validation

## Source evidence
- The pinned INA226 library `_readRegister()` returns `0` and stores an internal error when I2C transmission/read fails (`.pio/libdeps/esp32-s3-real/INA226/INA226.cpp:509-532`); it exposes `getLastError()`.
- `firmware-esp32/src/sensor/ina226.cpp:62-86` calls `getBusVoltage()` and `getCurrent()` but never checks `getLastError()` after either register read.
- Its range guards accept `0V` and `0A`, increment `s_readOk`, and return true.
- `ina226BuildRedundantReadings()` then duplicates that reading for every battery (`ina226.cpp:89-139`).
- BatteryService intentionally raises `SensorMismatch` when redundant voltage differs from BMS by more than 0.5V (`AnomalyRules.cs:211-228`).

## Reproduction
1. Boot real-BMS firmware with INA226 initially present so initialization succeeds.
2. Disconnect SDA/SCL or fault-inject `Wire.endTransmission()!=0` during polling.
3. The library returns zero for the failed register read.
4. Observe firmware count the poll as successful and publish a `redundant` reading with 0V/0A for every battery.
5. BatteryService compares a normal BMS voltage with 0V and creates false `SensorMismatch` alerts.

## Actual
I2C transport failure is indistinguishable from a valid electrical measurement and corrupts cross-source telemetry for all mapped batteries.

## Expected
Check the library error after each register access and reject the sample on any I2C failure. A single bus-level sensor must not synthesize a valid reading for every battery after a failed read.

## Impact
False safety alerts/tickets, misleading dashboards, and incorrect device health statistics during a common loose-wire/bus-reset failure.

## Acceptance criteria
- Check `getLastError()` after voltage and current reads; reject nonzero errors.
- Add finite/range validation and expose a read-failure metric/log.
- Fault-injection tests for NACK, short read, one-register failure, and recovery.
- E2E test proves no redundant row or `SensorMismatch` alert is created for an I2C transport failure.
