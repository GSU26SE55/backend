# #910 — [Shared][Security Logging] Raw query logging exposes unsubscribe tokens and OAuth code/state

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/910

---

## Component

`[Shared][Security Logging]` — request middleware logging of signed/query credentials across services.

## Source evidence

- `shared/src/SharedInfrastructure/Middleware/RequestLoggingMiddleware.cs:52-72` writes the complete `Request.QueryString` for every non-health request at Information/Warning/Error.
- `NotificationUnsubscribeController.cs:59-63,129-132` receives a signed one-click unsubscribe credential in `?token=`.
- `UnsubscribeTokenService.cs:27-29` gives that capability token a default 180-day lifetime.
- Auth `AuthController.cs:720-728` receives Google authorization `code` and CSRF `state` through query parameters.
- The shared middleware is installed across API services, so handler-level careful logging cannot prevent the leak.

## Steps to reproduce

1. Configure a capturing logger and call `/api/notification-unsubscribe?token=ROUND9_SECRET_SENTINEL` through the normal pipeline.
2. Exercise success and invalid-token responses.
3. Inspect request logs; repeat with a Google callback containing recognizable `code` and `state` sentinels.

## Actual result

The full signed token/code/state is stored verbatim in application and centralized logs. An unsubscribe token remains replayable to modify user preferences for up to 180 days.

## Expected result

Request logging preserves method/path/status/correlation and allow-listed safe query metadata only. Capability tokens, OAuth codes, CSRF state, signatures, API keys, and equivalent secrets are always redacted.

## Impact

Anyone with log access, exports, backups, or observability access can replay unsubscribe capabilities or OAuth callback material. Secret retention extends to the log lifecycle.

## Acceptance criteria

- Stop logging raw query strings; parse and allow-list safe parameter names or redact secret-name patterns centrally.
- At minimum protect `token`, `code`, `state`, `key`, `signature`, and case/alias variants.
- Ensure exception/4xx/5xx paths use the same redaction.
- Add capturing-logger tests through Notification and Auth routes proving sentinels never appear.
- Document incident response/rotation for query credentials already retained in logs.

## Dedupe note

Distinct from #873 (Google access/refresh tokens logged by a handler) and #895 (recipient/provider response logging); this is shared middleware leaking URL capability and OAuth callback secrets.
