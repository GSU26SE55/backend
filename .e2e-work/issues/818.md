# #818 — [Shared][Idempotency][Reliability] Exceptions and 5xx responses poison reservations and retries

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/818

---

## Component
Shared IdempotencyKeyMiddleware / Redis store

## Evidence
The middleware reserves a key before invoking the pipeline but has no delete/release operation when the pipeline throws. It caches every returned status, including 5xx. Redis reserve uses separate `HSETNX` and `EXPIRE` calls, so a crash between them can leave a permanent reservation.

## Actual
A transient exception can make all retries return conflict until expiry or forever; a transient 5xx can be replayed for 24 hours even after recovery.

## Expected / acceptance
Use an atomic script/transaction for reservation+TTL, release failed reservations, cache only explicitly safe outcomes, and add exception/crash/5xx retry tests.
