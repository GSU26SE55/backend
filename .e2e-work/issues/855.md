# #855 — [BatteryService][IoT][MQTT] QoS 0 subscription and automatic ACK silently lose failed telemetry

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/855

---

## Component
Battery MQTT bridge reliability

## Evidence
`MqttBridgeBackgroundService.cs:90-95` uses the string SubscribeAsync overload. With pinned MQTTnet 4.3.6 this defaults to AtMostOnce. Handler lines 143-175 catch processing exceptions and return normally while event auto-acknowledgement remains enabled.

## Actual
Even QoS1 publishers are delivered to the bridge at QoS0; transient mediator/DB failure is logged and lost with no redelivery. Merely changing subscription QoS later still auto-ACKs caught failures.

## Expected / acceptance
Subscribe explicitly at QoS1, acknowledge only after durable idempotent commit, implement bounded retry/DLQ/metrics for transient/poison messages, and add packet-level plus DB-failure/reconnect tests.
