## Scope

**Trong scope:**
- Đảo thứ tự: quyết định dedup/merge **trước**, `/prescribe` **sau** và chỉ trên nhánh thật sự sinh ticket.
- Đổi dedup từ *time-window-based* sang *status-based*: bỏ `DedupWindowEndUtc > now` khỏi điều kiện tìm alert active.
- Merge = **update in-place** alert đang mở (refresh `ActualValue` / `DetectedAt` / `DedupWindowEndUtc`), không insert row mới.
- Escalation `Degrading → Failed`: nâng `Severity` lên `Critical` + ghi Outbox V1/V2 một lần để tạo ticket.
- Loại `SohDegradation` khỏi `AlertAutoResolveService`.
- Migration one-off gộp các alert `SohDegradation` Open/Acknowledged trùng lặp đang tồn tại về 1 alert/asset.
- Unit test: multi-tick vượt qua cửa sổ dedup + assert `PrescribeAsync` không bị gọi khi dedup.

**Ngoài scope:**
- ai-module (Python) — không sửa `/predict`, `/prescribe`, model, hay RAG.
- Cùng bug time-window ở `AnomalyDetectionService` (threshold engine) — cấu trúc giống nhưng issue chỉ nói SOH.
- Thêm nhánh resolve riêng cho SOH (resolve khi prediction trở lại `Normal`) — để lần sau.
- Thêm config mới vào `AiOptions` — `AddHours(1)` giữ nguyên, giờ chỉ còn là trường bookkeeping, không còn điều khiển dedup.
- Ticket/SLA đã sinh ra từ 188 alert cũ — migration chỉ gộp alert, không đụng ticket.

## Approach

### 1. Lazy prescription — `/prescribe` không bao giờ chạy khi bị dedup

Thay vì gọi `PrescribeAsync` ở call site rồi truyền chuỗi kết quả xuống, truyền một **delegate**. `RaiseSohAlertAsync` chỉ `await` nó trên đúng nhánh ghi Outbox Critical. Cách này khiến việc "prescribe khi đã dedup" trở thành **bất khả thi về mặt cấu trúc**, thay vì phụ thuộc vào việc người sửa sau nhớ giữ đúng thứ tự lệnh.

```csharp
// RunTickAsync — thay cho block :168-183
if (result.Classification is AnomalyClassificationEnum.Degrading
    or AnomalyClassificationEnum.Failed)
{
    // Chưa gọi AI ở đây — chỉ đóng gói CÁCH gọi.
    Func<CancellationToken, Task<string?>> prescribeAsync = async token =>
    {
        if (!_options.PrescriptionEnabled) return null;
        var presc = await prescriptionClient.PrescribeAsync(
            asset.Id.ToString(), readings, enrich: true, packConfig, token);
        return BuildPrescriptionText(presc);
    };

    if (await RaiseSohAlertAsync(uow, asset.Id, asset.CustomerId, asset.SiteId,
            asset.SerialNumber, result, prescribeAsync, now, ct))
        alerts++;
}
```

### 2. Dedup theo status, merge in-place

```csharp
// RaiseSohAlertAsync — thay cho block :269-278
var existing = await uow.Alerts
    .GetAllAsync()
    .Where(a => !a.IsDeleted
                && a.BatteryAssetId == assetId
                && a.AnomalyType == AnomalyTypeEnum.SohDegradation
                && (a.Status == AlertStatusEnum.Open || a.Status == AlertStatusEnum.Acknowledged))
    // ❌ BỎ: && a.DedupWindowEndUtc > now  ← chính là nguyên nhân duplicate mỗi giờ
    .OrderByDescending(a => a.DetectedAt)
    .FirstOrDefaultAsync(ct);

if (existing is not null)
{
    // Escalate: alert đang mở là Warning (Degrading), prediction mới là Failed (Critical).
    // TicketId == null → chưa từng có ticket cho alert này, an toàn để bắn event.
    var escalating = severity == AlertSeverityEnum.Critical
                     && existing.Severity != AlertSeverityEnum.Critical
                     && existing.TicketId is null;

    existing.ActualValue       = result.SohPercent;
    existing.DetectedAt        = now;
    existing.DedupWindowEndUtc = now.AddHours(1);
    if (escalating)
        existing.Severity = AlertSeverityEnum.Critical;

    uow.Alerts.UpdateAsync(existing);   // VOID — không await

    if (!escalating)
        return false;                    // merge thuần → không alert mới, không prescribe, không ticket

    await WriteCriticalOutboxAsync(uow, existing, assetId, customerId, siteId, serial,
        await prescribeAsync(ct), now);  // prescribe CHỈ ở đây
    return true;
}
```

### 5. Migration cleanup

Bảng `alerts`, cột snake_case. `anomaly_type` = 8 (`SohDegradation`), `status`: Open=1, Acknowledged=2, Merged=3. Không xóa dữ liệu — chỉ chuyển các bản trùng sang `Merged` và trỏ `merged_into_alert_id` về bản mới nhất.

```sql
-- Up()
WITH keep AS (
    SELECT DISTINCT ON (battery_asset_id) id, battery_asset_id
    FROM alerts
    WHERE is_deleted = false AND anomaly_type = 8 AND status IN (1, 2)
      AND battery_asset_id IS NOT NULL
    ORDER BY battery_asset_id, detected_at DESC
)
UPDATE alerts a
SET status = 3, merged_into_alert_id = k.id
FROM keep k
WHERE a.battery_asset_id = k.battery_asset_id
  AND a.id <> k.id
  AND a.is_deleted = false AND a.anomaly_type = 8 AND a.status IN (1, 2);
```

`Down()` — đảo ngược đúng tập vừa đụng về `status = 1, merged_into_alert_id = NULL`.

> ⚠️ `Down()` không thể khôi phục chính xác alert nào vốn là `Acknowledged` (2) — tất cả sẽ về `Open` (1). Chấp nhận được: đây là cleanup dữ liệu rác, không phải schema change có thể mất data.

## Edge Cases

| Case | Xử lý |
|------|-------|
| Không có alert nào đang mở | Tạo alert mới như cũ; prescribe chạy nếu `Failed` |
| Alert đang mở, prediction vẫn `Degrading` | Refresh evidence + window, return false. Không prescribe, không ticket |
| Alert đang mở là `Warning`, prediction → `Failed` | Nâng `Severity`, prescribe, ghi Outbox → 1 ticket. Tick sau không lặp lại |
| Alert đang mở là `Critical`, prediction vẫn `Failed` | Chỉ refresh. Không prescribe, không ticket |
| Alert đang mở đã có `TicketId` | `escalating = false` → không bắn event lần hai |
| Alert ở trạng thái `Acknowledged` | Vẫn tính là unresolved → merge vào, không tạo mới |
| Alert đã `Resolved` / `Merged` | Không match → tạo alert mới (đúng: sự cố mới sau khi đã xử lý xong) |
| `PrescriptionEnabled = false` | Delegate trả `null`, không gọi AI; ticket vẫn tạo với prescription rỗng (giữ hành vi cũ) |
| `PrescribeAsync` throw / timeout | `try/catch` per-asset ở `:185-188` bắt được; chưa `SaveChangesAsync` → không commit nửa vời |
| Nhiều asset trong 1 tick | `SaveChangesAsync` vẫn gọi 1 lần cuối tick — không đổi |
