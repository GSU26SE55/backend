# #857 — [BatteryService][IoT][MQTT Commands] Offline commands enter an unbounded volatile queue without expiry

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/857

---

## Component
Backend MQTT command dispatch

## Evidence
The managed MQTT client is configured without durable storage or MaxPendingMessages. `MqttBridgeBackgroundService.cs:128-140` checks IsStarted, not IsConnected, then EnqueueAsync. MQTTnet distinguishes those states and defaults pending capacity to int.MaxValue. Controller payload adds issuedAt but no expiresAt; firmware ignores issuedAt.

## Actual
While broker is disconnected, API returns 202 and memory grows. Battery restart loses accepted commands; reconnect without restart executes arbitrarily stale commands.

## Expected / acceptance
Use a bounded durable command outbox/status and TTL, validate expiry on firmware, return 503 when durable acceptance is unavailable, expose failed/expired state and metrics, and test disconnect/restart/reconnect/overflow.
