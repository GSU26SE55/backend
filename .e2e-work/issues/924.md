# #924 — [IoT][INA226][Data Integrity] One physical measurement is cloned across every battery asset

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/924

---

## Component

`IoT firmware` — INA226 multi-battery cross-source telemetry.

## Summary

The real firmware instantiates and samples exactly one INA226, then copies that single bus voltage/current pair into a `redundant` reading for every battery serial returned by BMS polling. In the default four-battery setup, three batteries receive measurements from the wrong electrical circuit, which can create false SensorMismatch alerts/tickets or hide a real mismatch.

## Evidence

- `../iot/firmware-esp32/src/sensor/ina226.cpp:27` creates one `INA226` at one configured address.
- `ina226.cpp:89-100` samples that device once and explicitly says the same V/I is replicated for every battery.
- `ina226.cpp:101-136` loops through all serials and assigns the identical `v` and `i` to each battery identity with `sensorSourceCode="redundant"`.
- `../iot/firmware-esp32/src/bms/bms_source.cpp:77-84` passes every successfully polled battery serial to that replication method.
- `../iot/firmware-esp32/include/config.example.h:165-173` supports only a single INA226 address while the BMS path defaults to four units.
- `../iot/overall.iot.md:88-99` specifies 2–4 independent INA226 modules and per-battery cross-source measurement.
- `overall.md:7949,9685-9688` defines per-battery BMS-versus-INA226 validation, not one aggregate reading cloned across assets.

## Deterministic reproduction

1. Configure four battery mappings and connect the single configured INA226 to BAT-1 at 12.8 V / 1 A.
2. Let the other BMS devices report distinct values, e.g. BAT-2=25.6 V, BAT-3=48 V, BAT-4=51.2 V.
3. Call `bmsSourcePollAll` in real mode.
4. Observe four `redundant` records, all carrying 12.8 V / 1 A but labeled as BAT-1 through BAT-4.
5. Backend cross-source comparison treats each as a real measurement of its labeled battery.

## Actual result

One physical measurement is falsified as N independent battery measurements.

## Expected result

Each redundant reading must come from the INA226 physically mapped to that battery. If a battery has no independent sensor, no redundant reading should be emitted for it.

## Impact

- Healthy batteries can generate false voltage/current mismatch alerts and automatic P1/P2 tickets.
- A real failure may be hidden when a cloned value happens to match the wrong BMS.
- Historical telemetry attributes one circuit's measurement to unrelated assets.
- The system reports cross-source redundancy that the hardware/software path does not actually provide.

## Acceptance criteria

- Configure an explicit battery↔INA226 address/channel mapping and instantiate/poll each sensor independently.
- Never clone one physical measurement across multiple battery identities.
- Omit the redundant source for unmapped/unavailable sensors and expose per-sensor health.
- Add real-path tests with distinct per-battery voltages/currents and missing sensors.
- Add cross-repository E2E proving every redundant row maps to its own physical source.
