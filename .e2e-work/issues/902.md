# #902 — [IoT][CI][Security] Secret-history guard always fails even when no secrets are committed

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/902

---

## Component

`[IoT][CI][Security]` — `firmware-ci` infra secret-history gate.

## Source evidence

In `.github/workflows/firmware-ci.yml:148-155`, the check is written as:

```bash
if git log --all --diff-filter=A --name-only \
  | grep -E '\.key$|^infra/mqtt/mosquitto/passwd$' \
  | head -1; then
  echo "::error::Private key hoặc passwd file đã từng commit vào git history!"
  exit 1
fi
```

Without `set -o pipefail`, an empty pipeline still has the exit status of `head`, which is zero. Therefore the `if` body is taken even when `grep` found no secret file.

## Deterministic reproduction

Run the exact pipeline in the IoT repository where the secret filename query returns no line. The pipeline status is still `0`, and the condition enters the failure branch.

GitHub run `28217861637` confirms the impact: Compose validation and Shellcheck succeeded, then `Verify secrets NOT committed` failed. The latest eight listed `firmware-ci` runs all concluded `failure`; the firmware build job itself succeeded in that run.

## Actual result

The security guard reports a committed private key/passwd on a clean history result and makes `Infra config sanity` red unconditionally. A permanently red check cannot distinguish a real secret incident from the false positive and is likely to be ignored or bypassed.

## Expected result

The step fails only when a matching secret filename exists and succeeds otherwise, while preserving the match as audit evidence without printing secret contents.

## Impact

The repository has no trustworthy green CI baseline for MQTT infrastructure. Real secret regressions are hidden in constant noise, merge protection can be disabled/bypassed, and unrelated changes are blocked.

## Acceptance criteria

- Base the condition on `grep -q` (or enable `pipefail` and handle SIGPIPE correctly) instead of the final `head` status.
- Suppress secret contents; report only a safe path/count.
- Add a fixture/test proving no-match succeeds and a synthetic matched filename fails.
- Re-run the workflow and obtain a green `Infra config sanity` job on clean history.
- Keep an explicit incident/rotation path when a real historical secret is found.
