# #827 — [BatteryService][IoT] Calibration expiry dedupes the wrong entity and never notifies Manager

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/827

---

## Component
Calibration expiry worker

## Evidence
`CalibrationExpiryNotificationBackgroundService.cs:65-117` only inserts an Alert and writes no notification/outbox event. It dedupes by BatteryAsset + `SohDegradation` + seven-day window instead of calibration ID/channel. This conflicts with `overall.md:5138-5139`.

## Reproduction
Create two expiring calibrations on different channels for one asset, or create a genuine recent SOH alert before the scan. At most one/no calibration alert is created and Manager receives no notification.

## Expected / acceptance
Use a calibration-specific event/type, dedupe by calibration identity and notification window, publish an idempotent Manager notification, and cover multiple channels plus coexistence with SOH alerts.
