# #848 — [Helm][Security] Secret workflow deploys public placeholders and ignores externalSecretName

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/848

---

## Component
Helm secret management

## Evidence
- `templates/shared/secret.yaml:26-56` creates a Secret containing known placeholders when no Secret exists.
- The placeholder JWT key is shorter than Auth's validated minimum; Auth uses ValidateOnStart.
- `secrets.externalSecretName` defaults empty.
- Rendering with `--set secrets.externalSecretName=my-prod-secret` suppresses Secret creation but still emits 30 references to hard-coded `solar-secrets` and zero references to the configured name.

## Actual
Default install starts infrastructure with publicly known credentials and Auth crash-loops. A correctly supplied external Secret under another name produces CreateContainerConfigError.

## Expected / acceptance
Fail Helm install unless a real secret is supplied, never render functional placeholder credentials, centralize a secret-name helper for all env/envFrom references, and add schema/render tests for default, external-secret and missing-key cases.
