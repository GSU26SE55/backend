# #864 — [BatteryService][Hourly Aggregate] Optional time filters cause PostgreSQL 42P08 and HTTP 500

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/864

---

## Component
Sensor reading continuous aggregate endpoint

## Evidence
`SensorReadingAggregateViewReader.cs:19-26` uses `@from IS NULL` / `@to IS NULL`. Lines 48-49 pass DBNull through parameters without DbType, so PostgreSQL cannot infer timestamp types.

## Runtime reproduction
Authenticated GET `/api/sensor-readings/{id}/aggregate/hourly`:
- no filters: 500;
- only from: 500;
- both from and to: 200.

Logs confirm PostgreSQL `42P08: could not determine data type of parameter $2` at reader line 52. The same 500 occurred for Manager, Staff and Customer through Gateway.

## Expected / acceptance
Set NpgsqlDbType/DbType explicitly or build typed conditional SQL, preserve truly optional filters, return controlled errors only for invalid ranges, and add direct/Gateway integration tests for none/from/to/both.
