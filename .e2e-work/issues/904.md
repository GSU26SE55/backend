# #904 — [IoT][BMS][JK-BMS][Safety] Signed 32-bit current is truncated to 16 bits and reverses charge direction

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/904

---

## Component

`[IoT][BMS][JK-BMS][Safety]` — Modbus register decoding for the documented JK-BD6A24S10P/JK-BMS path.

## Source evidence

- `firmware-esp32/src/bms/bms_register_map.h:105-117` declares JK current at offset 2 as signed **int32**, scaled by `0.001 A`, and explicitly notes that only the low 16 bits are read.
- `firmware-esp32/src/bms/bms_register_map.cpp:37-45` always loads one `uint16_t`, casts it to `int16_t`, and applies the scale; the register-map type has no width/word-order metadata.
- `firmware-esp32/src/bms/modbus_bms.cpp:140-165` receives the full register array but sends it through that 16-bit decoder.
- The hardware assembly guide targets a JK-BD6A24S10P rated for 100 A continuous, so normal operating values exceed the signed-16-bit range at 0.001 A resolution (±32.767 A).
- Existing native tests cover JBD 16-bit positive/negative current only; there is no JK 32-bit boundary test.

## Deterministic reproduction

Encode two valid signed 32-bit JK values using the declared 0.001 A scale:

1. `+50.000 A` → raw `0x0000C350`. The current decoder uses low word `0xC350` as `int16_t -15536` and returns `-15.536 A`.
2. `-50.000 A` → raw `0xFFFF3CB0`. It uses low word `0x3CB0` as `int16_t 15536` and returns `+15.536 A`.

The sign and magnitude both become wrong above 32.767 A even though the Modbus read succeeded.

## Actual result

High charge current can be published as a smaller discharge current, and high discharge current as a smaller charge current. The payload is syntactically valid, so BatteryService persists and evaluates it rather than rejecting it as a sensor fault.

## Expected result

The JK decoder combines both registers with the model's documented word order, performs signed 32-bit conversion, applies the correct scale, and rejects impossible/out-of-range values instead of silently publishing them.

## Impact

Charging-state inference, power/energy calculations, anomaly detection, redundant-sensor comparison, maintenance decisions, and safety alerts can all be inverted during ordinary high-current operation on the documented 100 A rig.

## Acceptance criteria

- Extend register metadata/decoder support for 16-bit and 32-bit signed/unsigned fields plus explicit word order.
- Decode JK current from both registers according to the exact supported JK protocol/hardware revision.
- Add sanity limits and surface an invalid sensor read rather than a believable incorrect value.
- Add native vectors for `0`, `±32.767 A`, `±32.768 A`, `±50 A`, and documented extrema in both word orders.
- Add a hardware/recorded-frame comparison against the JK app or a protocol fixture and verify voltage/current/SOC across the whole supported range.
- Ensure downstream telemetry/alerts are not emitted from a failed decode.
