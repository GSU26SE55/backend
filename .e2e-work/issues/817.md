# #817 — [Shared][Idempotency][Security] Global raw keys replay cached responses across services, routes and users

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/817

---

## Component
Shared IdempotencyKeyMiddleware / Redis

## Evidence
`IdempotencyKeyMiddleware.cs:53-67` passes only the raw header value. `RedisIdempotencyKeyStore.cs:23-29,79` stores it as `idempotency:{key}`, without service, HTTP method, route, authenticated subject or request fingerprint.

## Runtime reproduction
1. POST Notification unsubscribe with key `e2e-fourth-cross-service-20260801a`; receive its 400 response.
2. POST Auth introspection with the same key and a different body.
3. Auth returns the exact cached Notification response body/status.

## Impact
A known/reused key can cross endpoints and services and may disclose another user's cached response, including sensitive auth responses.

## Expected / acceptance
Namespace by service/method/normalized route/subject and bind to a request-body hash; reject semantic key reuse; add cross-service, cross-route and cross-user isolation tests.
