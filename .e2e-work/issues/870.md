# #870 — [IoT][MQTT][Reliability] Connection is accepted when online publish or command subscription fails

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/870

---

## Component
IoT firmware — MQTT connection lifecycle and command channel

## Source evidence
- `firmware-esp32/src/net/mqtt_client.cpp:124-152` validates only the MQTT CONNECT result.
- After CONNECT, retained online publish and command subscription return values are only logged (`mqtt_client.cpp:159-169`).
- `tryConnect()` returns true unconditionally at line 171 even when either operation failed.
- `mqttTick()` retries setup only when `s_mqtt.connected()` is false (`mqtt_client.cpp:269-280`), so a connected session with a failed subscription is never repaired.
- `ota_update.cpp:381-401` also treats MQTT connected as OTA health, even if the command subscription failed.

## Reproduction
1. Allow MQTT CONNECT but fault-inject `PubSubClient::subscribe()` returning false, for example a transient socket/write/buffer failure immediately after CONNECT.
2. Observe log `subscribe ... FAIL` followed by the device remaining connected.
3. Let `mqttTick()` continue: it only calls `s_mqtt.loop()` and never retries the subscription.
4. Publish a backend command to `solar/{device}/cmd`; the device never receives it while telemetry may continue.

The same state can leave retained status as `offline` when the initial online publish fails.

## Actual
Transport connectivity is treated as full session readiness. Command downlink can remain disabled indefinitely and status can remain stale without reconnect/resubscribe.

## Expected
A session is ready only after required subscriptions and retained status publication succeed. Failures must trigger bounded retry or disconnect/reconnect, and OTA health must verify required application channels.

## Impact
Operators see a connected device that cannot receive heartbeat/interval/OTA commands; OTA can be confirmed healthy despite a broken downlink.

## Acceptance criteria
- Track CONNECTED versus SESSION_READY states.
- Retry or force reconnect when online publish/subscription fails.
- Confirm subscription success before marking OTA/application health.
- Add tests for failed publish, failed subscribe, reconnect, retained status repair, and command delivery after recovery.
