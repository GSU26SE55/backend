# #819 — [NotificationService][SignalR] WebSocket query-string access token is rejected

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/819

---

## Component
NotificationService SignalR authentication

## Evidence
Shared JWT setup accepts `access_token` from the query string only when the path contains `/stream` (`AddJWTAuthenticationAuthorization.cs:36-49`). Notification maps its hub at `/hubs/notifications` (`Program.cs:87`) and provides no override.

## Actual
Browser SignalR clients use query-string bearer tokens for a WebSocket handshake; the Notification hub does not extract that token, so authenticated WebSocket upgrade fails.

## Expected / acceptance
Handle `access_token` only for the exact trusted hub path, preserve header auth for other transports, and add negotiate + WebSocket integration tests through direct service and Gateway.
