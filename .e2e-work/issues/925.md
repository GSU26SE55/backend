# #925 — [AuthService][ApiGateway][JWT Revocation] Revoked tokens remain valid on every non-Auth backend service

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/925

---

## Component

`AuthService` / `ApiGateway` / all JWT-protected resource services.

## Summary

Logout, password reset/change, and admin force-revoke are enforced only inside AuthService. Gateway and every other backend service validate JWT signature/lifetime but never check revoked `jti` or account revocation cutoff. A token that AuthService rejects remains usable against Battery, Ticket, Notification, FileStorage, SMS, and Audit until natural expiry.

## Evidence

- `services/AuthService/src/AuthService.Api/Program.cs:138-142` is the only service registering token-revocation middleware.
- `TokenRevocationMiddleware.cs:27-46` contains the `jti` and account-cutoff checks.
- `shared/SharedInfrastructure/Extensions/AddJWTAuthenticationAuthorization.cs:18-33` validates signature, issuer, audience, and lifetime only.
- `services/ApiGateway/src/ApiGateway/Program.cs:117-129` parses/authenticates JWT then proxies without TRL/introspection.
- No resource service reads `revoked_jti`, `account_revoke_cutoff`, or calls `IsAccountFullyRevokedAsync`.
- `overall.md:5435` requires resource servers to enforce introspection/revocation.

## Reproduction

1. Login and obtain a valid non-expired JWT.
2. Logout, change/reset the password, or use admin force-revoke.
3. Confirm the old JWT now receives 401 from an AuthService protected endpoint.
4. Use the same token through Gateway or direct ports against allowed Battery/Ticket/Notification/FileStorage/SMS/Audit endpoints.
5. Requests remain authorized until JWT expiry.

## Impact

- Logout and account-wide security revocation do not log the user out of the system.
- A stolen token continues reading/mutating domain data after password reset or admin response.
- Role/session/permission changes cannot take effect promptly outside AuthService.

## Acceptance criteria

- Enforce both revoked `jti` and account cutoff consistently at Gateway and every resource server.
- Prevent bypass through direct service ports.
- Define fail-secure behavior when Redis/introspection is unavailable and monitor that state.
- Add cross-service integration tests: revoke one JWT, then require 401 from Auth, Battery, Ticket, Notification, FileStorage, SMS, and Audit.
- Cover logout, password reset/change, admin force-revoke, and expiry.
