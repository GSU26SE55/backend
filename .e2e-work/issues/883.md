# #883 — [IoT][Offline Queue][Reliability] Filesystem failures can discard both queued and replacement telemetry

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/883

---

## Component
IoT firmware — LittleFS offline queue durability

## Evidence
- At capacity, `firmware-esp32/src/queue/local_queue.cpp:134-142` deletes the oldest batch before attempting to open/write the replacement.
- If the replacement open/write fails at lines 152-164, enqueue returns false after the old batch is already gone; neither batch remains.
- `queuePeekOldest()` reads `fileSize` bytes but never checks `read == fileSize` (`local_queue.cpp:190-202`) and still returns true with a partial body.
- `main.cpp:302-315` posts that truncated JSON; a backend 4xx is classified permanent and the queued record is deleted.

## Reproduction A — full queue replacement
1. Fill the queue to `kMaxQueuedBatches`.
2. Fault-inject failure opening or completing the new body write.
3. Observe the oldest record deleted before the failed replacement and queue depth decrease with both data sets lost.

## Reproduction B — short read
1. Queue a valid JSON batch.
2. Fault-inject `readBytes()` returning fewer bytes than `fileSize`.
3. `queuePeekOldest()` returns true; backend rejects truncated JSON with 4xx; flush permanently deletes the original file.

## Actual
Filesystem I/O failures are converted into silent permanent telemetry loss and can lose two batches during one enqueue attempt.

## Expected
Queue replacement must commit new data before eviction or recover transactionally. Reads must verify exact length/integrity and retain/quarantine retryable local corruption rather than classify it as a backend data error.

## Acceptance criteria
- Use temp-file plus atomic rename/version/checksum and commit-before-evict semantics.
- Check exact write/read lengths and deletion results.
- Distinguish local corruption/I/O failure from backend permanent 4xx.
- Add full-queue, partial write/read, power-loss, reboot-recovery, and capacity invariant tests.
- Expose data-loss/quarantine metrics.
