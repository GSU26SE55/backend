# #833 — [IoT][Provisioning][NTP] Provisioned NTP settings are persisted but never applied

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/833

---

## Component
Firmware provisioning / time synchronization

## Evidence
Provisioning saves server/timezone configuration, but `time_sync` uses compile-time constants. Startup begins time sync before provisioning data is loaded and never reconfigures it afterward.

## Actual
Backend-provided NTP endpoints/timezone have no runtime effect, causing contract drift and incorrect/unavailable timestamps in deployments requiring custom NTP.

## Expected / acceptance
Load persisted settings before starting sync, apply changes after provision/refresh, define fallback behavior, and add native integration tests asserting the configured server/timezone reach the time subsystem.
