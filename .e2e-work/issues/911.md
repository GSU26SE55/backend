# #911 — [Shared][Pagination][Overflow] Extreme PageNumber wraps database offsets and causes 5xx

Priority: priority: P3
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/911

---

## Component

`[Shared][Pagination][Overflow]` — calculation of database offsets in Audit, Auth, Battery, Notification, and Ticket list handlers.

## Source evidence

- `shared/src/SharedContracts/Common/Requests/PaginationRequest.cs:9-18` normalizes non-positive values and caps `PageSize`, but has no maximum `PageNumber` or offset bound.
- At least 33 handlers calculate `Skip((PageNumber - 1) * PageSize)` using unchecked 32-bit integers.
- With `PageNumber=2147483647` and `PageSize=100`, the multiplication wraps to `-200`; EF/Npgsql translates that into an invalid negative OFFSET or otherwise fails the request.

## Steps to reproduce

Call a PostgreSQL-backed list endpoint using the shared request, for example an authorized Battery/Auth/Audit list route, with:

```text
?pageNumber=2147483647&pageSize=100
```

Inspect the generated offset and HTTP response.

## Actual result

The accepted positive page number overflows the offset calculation and can produce a 5xx/database error rather than an empty page or controlled validation response.

## Expected result

The API rejects an unrepresentable page/offset with 400/422, or calculates a safe checked 64-bit offset within a documented maximum.

## Impact

Any caller can induce repeatable exceptions across many list endpoints and pollute logs/availability using one query value.

## Acceptance criteria

- Define a shared maximum page/offset or calculate with checked `long` and validate provider limits.
- Return a consistent 400/422 ProblemDetails/CommonResponse for overflow/out-of-range input.
- Replace duplicated unchecked expressions with one safe pagination helper.
- Add shared boundary tests and at least one real PostgreSQL endpoint test for `int.MaxValue`, max valid, and max+1.
- Inventory all handlers so no alternate pagination DTO retains the same overflow.

## Dedupe note

Distinct from #797, which covers negative and unbounded pagination in specific Ticket chat/saga routes; this is positive integer overflow in the shared request across services.
