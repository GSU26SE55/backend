# #764 — [Shared][Reliability] Inbox claims messages before side effects and loses retries

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/764

---

## Tóm tắt
`ProcessOnceAsync` ghi Redis inbox marker trước khi chạy side effect. Nếu side effect lỗi, MassTransit retry cùng message id sẽ thấy marker và skip, khiến message bị ACK nhưng email, SMS, DB sync hoặc notification chưa từng hoàn tất.

## Bằng chứng source
- `shared/src/SharedInfrastructure/Idempotency/IdempotentConsumerExtensions.cs:20-34`: gọi `TryMarkProcessedAsync` trước `await action()`.
- `shared/src/SharedInfrastructure/Idempotency/RedisInboxStore.cs:23-32`: `SET NX` với TTL nhưng không rollback/delete khi action throw.
- Pattern này được dùng bởi EmailService, SmsService, BatteryService, TicketService và NotificationService.

## Tái hiện
1. Cho provider email/SMS hoặc DB đích lỗi ở lần consume đầu.
2. Marker inbox vẫn được tạo, action throw và MassTransit retry.
3. Retry gọi lại cùng IntegrationEvent.Id; `firstTime=false`, consumer return thành công và message bị ACK.

## Actual / Expected
- Actual: at-most-once trước side effect; lỗi tạm thời biến thành mất message vĩnh viễn.
- Expected: marker chỉ hoàn tất sau side effect thành công, hoặc dùng state processing/completed và rollback/lease an toàn.

## Acceptance criteria
- Retry sau side-effect failure thực thi lại action.
- Concurrent duplicate vẫn chỉ tạo một side effect.
- Thêm regression test: first attempt throws, second attempt succeeds, provider/DB được gọi đúng hai attempt và chỉ một kết quả cuối.
