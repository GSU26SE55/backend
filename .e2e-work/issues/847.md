# #847 — [Helm][FileStorageService][BatteryService][TicketService] Internal gRPC topology is missing

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/847

---

## Component
Helm deployment topology / internal gRPC

## Evidence
- FileStorage startup requires a distinct gRPC port and throws if absent: `FileStorageService.Api/Program.cs:12-17`.
- Its Helm Deployment/Service exposes only HTTP and sets no gRPC port.
- Ticket FileStorage client requires an absolute `FILE_STORAGE_GRPC_CLIENT_ADDRESS`: `TicketService.Infrastructure/DependencyInjection/ManageDependencyInjection.cs:207-214`.
- Battery binds gRPC on 8081: `BatteryService.Api/Program.cs:20-34`, but its Helm Service exposes only port 80.
- NetworkPolicy permits backend ingress only on 8080.
- Ticket's Battery client defaults to `batteryservice:8081`.

## Reproduction
`helm lint` passes, but rendered manifests contain no FileStorage gRPC server/client configuration and no FileStorage/Battery 8081 Service or NetworkPolicy path.

## Actual
FileStorage crash-loops; Ticket voice/file gRPC cannot resolve; Ticket→Battery sensor verification cannot connect in Helm deployment.

## Expected / acceptance
Render explicit HTTP2 ports and Services, configure client addresses, allow only required Ticket→FileStorage/Battery gRPC flows, and add an in-cluster gRPC smoke test to Helm CI.
