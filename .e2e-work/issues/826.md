# #826 — [BatteryService][Concurrency] Multi-replica workers duplicate anomaly, offline and escalation events

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/826

---

## Component
BatteryService background workers

## Evidence
Offline detection, threshold/anomaly detection, cross-source validation and alert escalation run on every replica and use check-then-insert/update. Relevant paths include `IotDeviceOfflineDetectionService.cs:35-101`, `AnomalyDetectionService.cs:92-128`, `CrossSourceValidationService.cs:96-132`, and `AlertEscalationService.cs:33-91`. No leader/claim, concurrency token or unique active-alert constraint protects them.

## Actual
The same stale device, reading/mismatch or critical alert can create duplicate alerts and distinct outbox events.

## Expected / acceptance
Add DB-backed atomic claims/conditional updates and appropriate unique partial constraints; run synchronized two-replica tests for each worker class and assert one durable effect.
