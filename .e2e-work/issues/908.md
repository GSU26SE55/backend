# #908 — [Production Compose][FileStorageService][Ticket Voice] Missing required gRPC settings make FileStorage crash-loop

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/908

---

## Component

`[Production Compose][FileStorageService][Ticket Voice]` — FileStorage gRPC server startup and TicketService transcription client wiring.

## Source evidence

- `FileStorageService.Api/Program.cs:14-18` requires either `FILE_STORAGE_SERVICE_GRPC_SERVER_PORT` or `Grpc:Port` and throws during startup when neither exists.
- `docker-compose.prod.yml:278-311` configures/publishes only HTTP 8080 for FileStorage and supplies no gRPC server port.
- `env.prod.example:282-313` also omits the required server setting.
- `FileStorageService.Api/Dockerfile:24-26` only exposes 8081; `EXPOSE` does not configure Kestrel or satisfy the startup guard.
- TicketService `ManageDependencyInjection.cs:209-215` requires an absolute `FILE_STORAGE_GRPC_CLIENT_ADDRESS` or `Chat:Voice:FileStorageGrpcAddress`.
- Production Compose/env provides neither client URI. `overall.md:17408` explicitly requires both service-scoped settings.

## Steps to reproduce

1. Fill only the documented placeholders in `env.prod.example` and start `docker-compose.prod.yml`.
2. Observe FileStorage throw before DB/application startup because the gRPC server port is absent.
3. Add only the server port and start TicketService; invoke the chat voice/transcription flow.
4. Observe the FileStorage gRPC client cannot resolve a configured absolute address.

## Actual result

The production FileStorage container crash-loops. Fixing that setting alone still leaves Ticket voice unable to call `DownloadForTranscription`.

## Expected result

Production declares a stable internal HTTP/2 gRPC listener and wires TicketService to the FileStorage service name while retaining the HTTP API listener.

## Impact

All production file operations are unavailable, and voice transcription cannot retrieve audio. Dependent Ticket flows fail despite images building successfully.

## Acceptance criteria

- Configure FileStorage internal gRPC on port 8081 and expose it only inside the Compose network.
- Configure TicketService with `http://filestorageservice:8081` (or the exact service DNS/port used).
- Add both variables to production Compose and the safe env template with startup validation.
- Run a production-profile smoke test for FileStorage HTTP plus HTTP/2 `DownloadForTranscription` from TicketService.
- Fail CI when either server/client setting is absent or not an absolute internal URI.

## Dedupe note

Distinct from #847, which covers missing gRPC topology in Helm/Kubernetes; this is the production Compose profile and its env contract.
