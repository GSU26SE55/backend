# #863 — [Kubernetes][Reliability] Readiness probes use metrics or static endpoints and ignore dependencies

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/863

---

## Component
Helm readiness/liveness

## Evidence
Auth, Battery, Ticket, Notification, FileStorage, Email and SMS readiness probes hit `/metrics`; Gateway `/health` is static; Audit `/ready` always returns 200. Battery's own health documentation states it does not validate DB, RabbitMQ or Redis.

## Actual
After database/broker/storage loss, Kubernetes keeps routing traffic to pods that cannot serve required operations. Deployment rollout can be marked ready before cross-service paths work.

## Expected / acceptance
Implement tagged liveness/readiness checks, include only service-critical dependencies in readiness with bounded timeout, keep liveness independent of external outages, and add fault-injection rollout tests for DB/broker/storage/downstream loss.
