# #859 — [BatteryService][IoT][MQTT Commands] Backend accepts command types firmware always rejects

Priority: priority: P3
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/859

---

## Component
Backend ↔ firmware command contract

## Evidence
`IotDeviceCommandDtos.cs:6-15` advertises reboot, ota, calibrate, sample-now, set-config and more. Controller validates only non-empty type and returns 202. Firmware `cmd_logic.cpp:33-38` recognizes only set_interval, request_heartbeat and trigger_ota; all others ACK unknown. ACK outcome is not surfaced to the original caller.

## Actual
Documented commands are accepted but never execute.

## Expected / acceptance
Define one versioned shared command/capability schema, reject unsupported types/parameters synchronously or per firmware capability, expose asynchronous command status, and contract-test every advertised command.
