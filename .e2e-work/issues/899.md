# #899 — [SmsService][Daily Quota] Multiple unreported claims bypass the gateway daily limit

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/899

---

## Component

`[SmsService][Daily Quota]` — gateway claim reservation and `DailyLimit` enforcement.

## Evidence

- `ClaimPendingMessagesCommandHandler.cs:42-56` computes allowance only from `SentToday`.
- `:58-83` moves claimed messages to `Sending` without reserving quota.
- `ReportSmsResultCommandHandler.cs:52-57` increments quota only after a later `Sent` report.
- `SmsGatewayDevice.cs:52-56` increments `SentToday` without enforcing the upper bound.
- Existing tests cover one claim batch, not repeated or parallel claims before reports arrive.

## Steps to reproduce

1. Set a gateway to `DailyLimit=1`, `SentToday=0` and enqueue two pending SMS messages.
2. Call claim with `limit=1` twice before reporting the first message.
3. Send and report both claimed messages.

## Actual result

Both claim calls return work because `SentToday` remains zero until reporting. Both messages are sent and the counter reaches two, exceeding the configured daily cap.

## Expected result

Claiming reserves capacity atomically. At every point, completed plus reserved work is at most `DailyLimit`; failed, cancelled, or stale work releases its reservation safely.

## Impact

The service can exceed carrier/budget limits, create unplanned cost, and violate operational controls. Concurrent gateway polling makes the overshoot larger.

## Acceptance criteria

- Add an atomic quota reservation during claim.
- Release/reconcile reservations for failed, cancelled, and stale messages.
- Enforce `completed + reserved <= DailyLimit` under sequential and concurrent requests.
- Add real PostgreSQL integration tests for repeated and parallel claims and midnight/reset behavior.
- Ensure retries/idempotent claims do not leak or double-release reservations.

## Verification performed

Current SMS claim/report tests pass (27/27), but no test exercises a second claim before the first report.
