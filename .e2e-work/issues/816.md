# #816 — [Production][Kubernetes][HTTPS] HTTP-only pods redirect after TLS termination; Ticket ignores disable override

Priority: priority: P1
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/816

---

## Component
ASP.NET HTTPS middleware / Helm / production Compose

## Evidence
Services listen on HTTP in Helm while staging runs outside the Docker environment and terminates TLS at ingress. They call `UseHttpsRedirection` without trusted forwarded-proto handling. Helm does not set `DisableHttpsRedirection`. TicketService `Program.cs:145-146` ignores that configuration switch and checks only the Docker environment, although production Compose is HTTP-only.

## Actual
Requests can redirect repeatedly to the same external HTTPS URL after TLS termination; Ticket production Compose can also redirect its HTTP-only internal traffic.

## Expected / acceptance
Honor forwarded proto from trusted ingress or disable app redirect behind TLS termination, make Ticket honor the same explicit setting, and add staging/production reverse-proxy tests proving one request reaches each service without a loop.
