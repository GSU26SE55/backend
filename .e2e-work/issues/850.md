# #850 — [BatteryService][Ambient] Invalid and future telemetry is persisted and poisons latest readings

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/850

---

## Component
Ambient batch ingestion

## Evidence
`BatchIngestAmbientReadingsCommand.cs:18-56` validates batch size, SiteId, humidity and temperature, but not timestamp skew/UTC, negative solar irradiance, undefined Source enum or SourceDeviceId length. The handler persists fields directly; DB mapping lacks irradiance/source checks. `AmbientQueryHandlers.cs:65` selects latest by greatest timestamp.

## Reproduction
Submit a valid-site sample dated 2099 with negative irradiance and source=999: validation accepts/persists it and latest is permanently dominated. SourceDeviceId over 64 chars reaches PostgreSQL and becomes 500.

## Expected / acceptance
Return controlled 400/422 for non-UTC/future timestamps, negative irradiance, undefined enum and oversized identity; add DB constraints and verify rejected future data cannot poison latest.
