# #812 — [AuthService][ApiGateway][RateLimit] Gateway client IP is not restored, making anonymous limits global

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/812

---

## Component
AuthService / ApiGateway / security middleware

## Evidence
- `AuthService.Api/Extensions/RateLimitingExtensions.cs:31-40,61-70` partitions anonymous traffic by `HttpContext.Connection.RemoteIpAddress`.
- No service configures `UseForwardedHeaders`.
- `ClientInfoHelper.cs:35-46` independently trusts raw `X-Forwarded-For` for audit/session metadata.

## Runtime reproduction
Send 12 invalid login requests through ApiGateway with twelve distinct `X-Forwarded-For` addresses. The first ten return 400 and requests 11-12 return 429. AuthService sees the Gateway container IP for all clients.

## Actual
Unrelated internet users share one anonymous Auth limiter behind Gateway. Direct access can also spoof audit/session IP using an untrusted header.

## Expected / acceptance
Configure trusted forwarded headers before rate limiting, restrict known proxies/networks, use the normalized client IP consistently, and add proxy/NAT isolation plus spoofing regression tests.
