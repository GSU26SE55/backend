# #851 — [BatteryService][TicketService][AI Contract] Unknown SOH is encoded as measured 0 percent

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/851

---

## Component
Battery internal gRPC → Ticket AI verification

## Evidence
Sensor SOH is nullable. `BatteryInternalService.cs:40-52` searches history, then coerces all-null history to 0. The proto and Ticket DTO use non-nullable double with no presence/validity flag. `AiTicketVerifyGrpcClient.cs:35-48` marks the snapshot present and forwards SOH=0 to AI.

## Actual
“No SOH measurement exists” becomes “measured SOH is 0%”, which can create a false failed-battery assessment or make a legitimate ticket appear suspicious.

## Expected / acceptance
Preserve per-metric presence via proto optional/wrapper/validity flags, have AI ignore unknown metrics, and add a contract test for an asset with readings but no historical SOH.
