# #856 — [BatteryService][IoT][OTA] Firmware compatibility ignores hardware revision and device model

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/856

---

## Component
Firmware assignment and device update check

## Evidence
Firmware releases declare HardwareRevision/DeviceModel, but `IotDeviceCommandHandlers.cs:36-56` validates only existence/publication/archive state and can overwrite device hardware independently. `DeviceLifecycleHandlers.cs:208-256` checks only target state/version. IotDevice has no DeviceModel.

## Reproduction
Assign a published REV-B/model-B release to a REV-A or unknown-revision device. Assignment succeeds; firmware-check returns UpdateAvailable/artifact and creates a pending update log.

## Expected / acceptance
Persist trusted model/revision, reject missing/mismatched assignment atomically, revalidate during authenticated firmware-check, create no log on mismatch, and add exact/missing/case/model/revision compatibility tests.
