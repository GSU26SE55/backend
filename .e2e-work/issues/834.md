# #834 — [IoT][MQTT Commands] QoS1 redelivery re-executes non-idempotent side effects

Priority: priority: P2
State: OPEN
URL: https://github.com/GSU26SE55/backend/issues/834

---

## Component
MQTT downlink command execution and ACK bridge

## Evidence
Backend sends commands with QoS1. Firmware does not durably track processed `cmdId` values, and the ACK bridge records only raw acknowledgements without enforcing an execution state machine.

## Actual
Normal QoS1 redelivery or reconnect can repeat reboot, OTA or configuration side effects for the same command.

## Expected / acceptance
Persist a bounded processed-command ledger/state machine, return the prior ACK for duplicates without re-execution, correlate backend command status durably, and test redelivery across reconnect/reboot.
